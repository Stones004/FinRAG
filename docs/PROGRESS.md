## M00 notes (2026-10-11)
Assumptions and small additions beyond the spec text, all approved in review unless marked (new):
- **Fiscal labels:** a fiscal year is labelled by the calendar year in which it ends, for any `fy_start_month` (April FY26 = Apr 2025–Mar 2026; January FY26 = calendar 2026). Two-digit labels are read as 20yy. The label parse regex is derived from `fiscal.fy_label_format`.
- **`components_of(period)`** returns discrete quarters (FY → Q1..Q4, H1 → Q1,Q2, H2 → Q3,Q4, 9M → Q1..Q3; `[]` for a quarter). **`cumulative_steps(period)`** returns one-step `Identity` objects: H1 = Q1+Q2, 9M = H1+Q3, FY = 9M+Q4, H2 = FY−H1. (new) It also returns the discrete-quarter identities Q2 = H1−Q1, Q3 = 9M−H1, Q4 = FY−9M, which MASTER_BUILD §8.5 needs for derived quarters.
- **Review fixes (2026-10-11):** `label_to_period` accepts the space-less form (`Q1FY27`, `H2FY26`, `9MFY26`); `period_to_label` still outputs the spaced form. `cumulative_steps` now returns every route, fewest derived inputs first: FY = 9M+Q4, then FY = H1+H2; Q4 = FY−9M, then Q4 = H2−Q3. H2 counts as a derived input because it is never filed directly. Ranking is structural only: M05 must filter routes by which periods it actually has (e.g. no Q3 or 9M filings in the real data).
- **Env overrides:** only allowlisted secret keys (`alerts.email.password` → `FINRAG_ALERTS__EMAIL__PASSWORD`). Any other `FINRAG_*` variable is a `ConfigError` naming the variable. `alerts.email.password` is a model field defaulting to `""`; it is not in `settings.yaml`.
- **Strict settings:** unknown keys are rejected (`extra="forbid"`). Blank `[VERIFY]` values load fine; the module that needs one must fail clearly when it is still blank.
- **`finrag init`** creates only missing folders (data, raw, processed, indexes, reference, inbox, logs) and missing tables; it never modifies existing files (tested).
- **Dependencies:** base = pydantic, pyyaml, sqlalchemy, typer; `dev` = pytest, pytest-mock, ruff. Heavy packages are optional extras by module: `parsing`, `narrative`, `ui`, `llm`, plus (new) `watchlist` (rapidfuzz), `ingestion` (httpx, lxml) and `faiss`. Install each only when its module is built.
- **Schema (new):** `schema_version` table (constant `SCHEMA_VERSION = 1` in `db.py`); foreign keys only where the §7 text says FK, enforced via `PRAGMA foreign_keys=ON`; extra indexes on `filings`, `parsed_facts`, `canonical_facts`, `metric_values`, `chunks` (no column changes). `canonical_facts` append-only is not enforced by triggers yet — propose in M05 if wanted.
- **`JobStatus`** enum (running | succeeded | failed) added to `core/types.py` for the `jobs` table (new).
- **Logging** configures the `finrag` logger (propagate off), not Python's root logger, so other libraries' logs don't land in `finrag.log`.
- **Tests** use an autouse fixture that copies `settings.yaml` into a temp repo root, so tests never touch the real `data/`. `INSTANT` periods have no fiscal label and `shift_period` rejects them.
- Ran `finrag init` once on the real repo: created `data/raw`, `processed`, `indexes`, `logs` and `data/finrag.db`; `data/inbox` and `data/reference` were left as they were.

## M01 notes (2026-10-11)
- **Shared ISIN validator:** `is_valid_isin` / `looks_like_isin` / `ISIN_PATTERN` in `core/types.py` (Luhn check digit), tested with INE0NT901020 (valid) and INEONT901020 (invalid). M02 reuses it. In M01 an identifier shaped like an ISIN but failing the check digit is `not_found` with a review item saying so; it never falls through to symbol or name matching.
- **Alias types:** `AliasType` enum (`symbol|code|name|user|isin|scrip_code`) added to `core/types.py`; MASTER_BUILD §7.1 and the `db.py` comment updated. M01 writes `symbol`, `code` (BSE code), `name` and `user` only. `isin` aliases (old ISINs) are for M02; `scrip_code` is allowed but unused, since the master's BSE code is stored as `code`.
- **Securities master:** NSE columns mapped from the real `nse_equity_list.csv` (headers and values whitespace-stripped). **TODO:** `BSE_COLUMNS` in `watchlist/master.py` are unverified placeholders, tested only with a synthetic file; fix them when a real BSE file exists. A missing BSE file is a logged warning (so it also prints on the console), a missing NSE file is an error. The name-noise words (`LTD`, `LIMITED`) are a constant in `master.py`, as the spec places them there.
- **Resolver:** order ISIN, NSE symbol, BSE code, exact normalised name, fuzzy (`token_sort_ratio`, `watchlist.name_match_min_score`). Several candidates, exact or fuzzy, give `ambiguous`, never a pick.
- **Sync rules:** entity `name`/`nse_symbol`/`bse_code` come from the master; `sector_type` only from the watch list file (default from settings, never inferred); `default_basis` from the file or `defaults.basis`. A company missing from the file, or marked `status: paused`, becomes `paused`; adding it back or `status: active` reactivates it. Both appear in `SyncReport.paused` / `.reactivated` (and in `updated`). Entries that fail to resolve go to `review_queue` as `entity_ambiguous`; repeats increment `occurrences` on the open item. An unresolved entry whose text is already an alias of a tracked entity does not cause that entity to be paused. A second file entry resolving to an already listed ISIN is reported as `duplicate` (and queued).
- **Rename detection depends on refreshing the master file.** A rename is only seen when `nse_equity_list.csv` is re-downloaded after the change. The old symbol/name alias gets `valid_to` = sync day and the new one `valid_from` = sync day (the real change date is not known); a `corporate_events` rename row is written with `source = securities_master`.
- **"Today":** `settings.app.timezone` is used when the tz database is available. The `tzdata` package is not installed on this Windows machine, so the code falls back to the local date. Not added as a dependency; ask if you want it.
- **Not done (not in spec):** an open `entity_ambiguous` item is not auto-resolved when the entry later resolves; no `basis_change` event is recorded when the file's `basis` changes.

## M02 notes (2026-10-12)
Decisions from review and what was built beyond the spec text:
- **Quarantine:** new `FilingStatus.QUARANTINED` and review item types `filing_conflict` and `inbox_unrecognised` (MASTER_BUILD §7 comments, `db.py` comments and M02 spec updated). A file whose content conflicts with its filename/listing (ISIN check digit or ISIN mismatch, period start/end, period type, basis, transcript title quarter) is stored in the raw store and registered `quarantined`; the review item lists each conflict and, when one exists, the revision that supersedes it (kept current when the revision arrives later, either order). `finrag ingest release <id>` makes it `fetched`; `ingest ignore <id>` keeps it quarantined. ### 2026-10-11 — data spike (Gabriel, HDFC Bank, Netweb; 17 XBRL + 4 PDFs from NSE)
Files: `data/inbox/`, provenance in `data/reference/inbox_manifest_2026-10-11.csv`.

1. **Two NSE result sources.** `/api/corporates-financial-results` (old format) only has results up to ~Dec 2024.
   From the FY25 Q4 results onward, results are under **Integrated Filing – Financials**:
   `/api/integrated-filing-results?index=equities&symbol=X&type=Integrated%20Filing-%20Financials&from_date=DD-MM-YYYY&to_date=DD-MM-YYYY`
   (fields: `qe_Date, consolidated, audited, type_Sub (Original|Revision), broadcast_Date, xbrl, ixbrl, pdf_attach`).
   Annual reports: `/api/annual-reports?index=equities&symbol=X` (field `fileName`). Files live on `nsearchives.nseindia.com`.
   The API needs NSE browser cookies (works from a page on nseindia.com; plain HTTP clients are typically blocked). → M02.
2. **API metadata can be wrong.** The old API lists HDFC Bank as `INE040A01018` (pre-split ISIN); the XBRL and NSE equity list say `INE040A01034`. → ISIN comes from file content or the securities master, never the listing API. Old ISINs go into `entity_aliases`.
3. **Filer errors are real and get revised.** Netweb's FY25 and FY26 Q4 originals are tagged `TypeOfReportingPeriod = Half Yearly` with period Oct–Mar (H2); the FY26 original also has ISIN typo `INEONT901020` (letter O). Revisions (`type_Sub = Revision`) correct these. Gabriel FY26 Q4 consolidated also has a revision. → Revisions are separate filings; filenames use `__rev<N>`; ISIN typo should be caught by ISIN check-digit validation and sent to review.
4. **Taxonomy:** namespace `in-capmkt` (`http://www.sebi.gov.in/xbrl/2026-01-31/in-capmkt`); file comment gives version (e.g. `IFIndAs V2.1`). Two families: `INTEGRATED_FILING_INDAS_*` (companies) and `INTEGRATED_FILING_BANKING_*` (banks). Banks use different concepts: `InterestEarned`, `InterestExpended`, `OperatingExpenses`, `ProvisionsOtherThanTaxAndContingencies`, `ProfitLossFromOrdinaryActivitiesBeforeTax`, `ProfitLossForThePeriod`, `Deposits`, `Advances`, `Borrowings`, `CapitalAndLiabilities`. Companies use `RevenueFromOperations`, `ProfitBeforeTax`, `ProfitLossForPeriod`, `Assets`, `EquityAndLiabilities`, `Equity`, `CashFlowsFromUsedInOperatingActivities`, etc. → M04 taxonomy.
5. **Filing-level metadata elements** (for `ingestion/xbrl_meta.py`): `ISIN`, `Symbol`, `ScripCode`, `NameOfTheCompany`, `NatureOfReportStandaloneConsolidated` (`Standalone|Consolidated`), `DateOfStartOfReportingPeriod`, `DateOfEndOfReportingPeriod`, `TypeOfReportingPeriod`, `ReportingQuarter`, `WhetherResultsAreAuditedOrUnaudited`, `LevelOfRounding` (`Millions|Crores|…`).
6. **Values are full rupees** with a `decimals` attribute (e.g. `-4`, `-6`); `LevelOfRounding` is presentation only — do not multiply. Unit `INR`.
7. **What each filing contains (no dimensions):** Q1/Q3: quarter P&L only (+ few instants). Q2: quarter + H1 P&L, balance sheet at 30 Sep, H1 cash flow. Q4: quarter + FY P&L, balance sheet at 31 Mar, FY cash flow. **No prior-period comparatives** are tagged → restatements are detected from revisions and later filings, not from comparative columns.
8. **Dimensions:** segment data uses `ReportableSegments<N>Member`; other-expense breakdown uses `OtherExpenses<N>Member`. Facts with dimensions must not be mixed with entity totals.
9. **Netweb files standalone only** (no subsidiaries) → `basis: standalone` in watchlist.
10. **PDFs:** annual reports have text layers. Netweb's Q4 results PDF is a scan with a poor embedded OCR layer ("prolit", "OPERATINC") → the PDF parser must score text quality, not just character count, before trusting a text layer. Statement pages: p.6 P&L, p.7 balance sheet, p.8 cash flow; unit "₹ in millions".
11. **Golden values** in `tests/golden/golden_values.yaml` are a DRAFT taken from XBRL (`verified: false`). They must be checked against PDFs before being used to test the XBRL parser.

## Open decisions
- 2026-10-11 — Narrative sources: earnings call transcripts become the primary narrative source for quarterly "why" questions; annual reports are limited to whitelisted sections (`narrative.annual_report_sections_include`). Rationale: annual reports run 130–680 pages and are mostly irrelevant to financial questions, but the auditor report, notes, related-party and contingent sections are required for the later shenanigans work, so annual reports are kept (whitelisted, with skipped pages recorded in a per-filing summary), not dropped. Specs updated: MASTER_BUILD §1.1/§7.2/§7.5, M02, M08, M09, settings.yaml.
- 2026-10-11 — Decisions recorded with this spec revision:
  1. Transcripts as a narrative source (`earnings_call_transcript`, PDF, period = quarter discussed): they are where management explains quarterly results, and annual reports cannot answer quarterly "why" questions. NSE listing uses corporate announcements (subject "Analysts/Institutional Investor Meet/Con. Call Updates", attachment text mentions "transcript"); response field names are still to verify from real responses. Link-only cover letters go to `review_queue` as `transcript_link_only`.
  2. Annual reports limited to whitelisted sections (`narrative.annual_report_sections_include`); skipped pages recorded in a per-filing summary (`not_whitelisted` | `unknown_section`).
  3. OCR behind an `OcrBackend` interface, `parsing.ocr.backend: tesseract | chandra` (Chandra via an OpenAI-compatible vision endpoint in LM Studio): scanned results PDFs have unreliable embedded text layers, and a stronger OCR model may read tables better. OCR numbers are never trusted over XBRL. The `ocr_*` keys moved from `parsing.pdf` to `parsing.ocr`. Chandra model name and output layout are unverified.
  4. LLM provider `openai_compatible` (LM Studio default, `http://localhost:1234/v1`): one interface covers LM Studio and Ollama; `llm/ollama.py` replaced by `llm/openai_compat.py`. Model name left blank until a 3–4B instruct GGUF is chosen.
  5. Hardware constraint recorded (RTX 4050 6 GB, 16 GB RAM): one GPU model at a time (OCR at ingestion, LLM at query time); embeddings on CPU (`narrative.embedding_device: cpu`).
- 2026-10-11 — Period handling for transcripts in the planner: H1/9M questions search transcripts for every quarter in the period; annual-report sections only when the period ends at fiscal year-end; FY questions use all four quarterly transcripts plus annual-report sections; citations are tagged with their quarter.
